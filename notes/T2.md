# Ticket T2: Searching near Fiji returns no results

## Brief Summary
- **Issue Name:** Searching near Fiji returns no results
- **Issue Explanation (Brief):** When searching near Fiji, the bounding box crosses the $180^\circ$ antimeridian (international date line) from $177^\circ\text{ E}$ to $178^\circ\text{ W}$ (`min_lon = 177, max_lon = -178`). Because `min_lon > max_lon`, the spatial R-tree query generated `WHERE r.minx <= -178 AND r.maxx >= 177`, which required a single scene to span almost the entire world, resulting in 0 matches.
- **Solution Explanation (Brief):** In `orbit/catalog/spatial.py`, detected when `min_lon > max_lon` and split the search into two separate queries across the date line: `[min_lon, 180.0]` and `[-180.0, max_lon]`, returning the union of scene IDs. Also normalized wrapped coordinate inputs in `parse_bbox()` and updated `drawBox.ts` to properly handle dragging across the antimeridian.

---

## What Was Seen
When drawing a search bounding box over Fiji spanning both sides of the date line (e.g. from 177° E to 178° W, latitude 20° S to 15° S), the portal returns "No scenes found" (0 scenes). However:
- A smaller search box on only the west side returns scenes.
- A smaller search box on only the east side returns scenes.
- Direct API query `GET /search?bbox=177,-20,-178,-15` returns 0 scenes even though 12 scenes exist in the database for Fiji.

## Reproduction Steps
1. In the catalog API, perform: `GET /search?bbox=177,-20,-178,-15`.
2. Notice the response:
   ```json
   { "type": "FeatureCollection", "numberMatched": 0, "numberReturned": 0, "features": [] }
   ```
3. Contrast with a query on either side alone:
   - `GET /search?bbox=177,-20,180,-15` returns 5+ scenes.
   - `GET /search?bbox=-180,-20,-178,-15` returns 5+ scenes.

## Root Cause
- **Antimeridian ($180^\circ$ / $-180^\circ$) Crossing:**
  - A bounding box spanning across the date line has `min_lon > max_lon` (e.g., $177^\circ > -178^\circ$).
  - In `orbit/catalog/spatial.py`:
    ```python
    def candidate_ids(db, min_lon, min_lat, max_lon, max_lat):
        rows = db.execute(
            "SELECT DISTINCT i.scene_id FROM scene_rtree r JOIN scene_index i ON i.rid = r.rid "
            "WHERE r.minx <= ? AND r.maxx >= ? AND r.miny <= ? AND r.maxy >= ?",
            (max_lon, min_lon, max_lat, min_lat),
        ).fetchall()
        return [r["scene_id"] for r in rows]
    ```
  - Substituting `max_lon = -178` and `min_lon = 177` yields:
    `WHERE r.minx <= -178 AND r.maxx >= 177`
  - In SQLite's R-tree spatial index, `r.minx` and `r.maxx` are coordinates on a planar coordinate system. No individual scene footprint has both $\text{minx} \le -178$ and $\text{maxx} \ge 177$ (that would mean a scene spanning 355 degrees of longitude).
  - Furthermore, scenes crossing the date line are already stored in the R-tree as two split halves (`[minx, 180.0]` and `[-180.0, maxx]`) in `db.py`, but the search lookup failed to split the query bounding box similarly.

## The Fix
1. In `orbit/catalog/spatial.py`:
   - Split queries where `min_lon > max_lon` into two bounding box queries:
     - Eastern side: `(min_lon, min_lat, 180.0, max_lat)`
     - Western side: `(-180.0, min_lat, max_lon, max_lat)`
   - Aggregate the matching candidate `scene_id`s across both queries using a set union.
2. In `orbit/catalog/app.py`:
   - In `parse_bbox()`, normalize longitudes so unwrapped drag coordinates from map libraries (e.g., longitude > 180 or < -180) wrap correctly to `[-180, 180]`.
3. In `web/src/map/drawBox.ts`:
   - Added logic to detect when the mouse drag crosses the date line (i.e. $|\text{start.lng} - \text{end.lng}| > 180$), appropriately setting `west` and `east` to preserve the antimeridian-crossing bounding box.

## How We Know It Works
1. **Automated Tests:**
   - Added `test_t2_search_across_dateline_fiji` in `tests/test_t2_t3.py`.
   - Running `GET /search?bbox=177,-20,-178,-15` now returns exactly `numberMatched: 12` matching the 12 seeded scenes around Fiji (5 west, 5 east, 2 crossing).
   - Also verified that unwrapped coordinates (`bbox=177,-20,182,-15`) return 12 scenes.
2. **Web Build:**
   - Ran `npm run build` in `web/` cleanly without any errors.
