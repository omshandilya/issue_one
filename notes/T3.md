# Ticket T3: An analyst saw scenes from another unit

## Brief Summary
- **Issue Name:** An analyst saw scenes from another unit
- **Issue Explanation (Brief):** When an analyst in Unit A searched an area containing Unit A restricted scenes (such as Gulf of Kutch), the catalog returned restricted scenes and marked the HTTP response as `Cache-Control: public, max-age=60`. The gateway proxy cached this response using a key constructed strictly from the HTTP method, path, and query string without including the `Authorization` header. When an analyst in Unit B ran the identical search shortly thereafter, the gateway served the cached response containing Unit A's restricted scenes.
- **Solution Explanation (Brief):** In `orbit/gateway/cache.py`, updated `ResponseCache.key` to include the `Authorization` header so cache entries are partitioned by user identity, and prevented caching responses with `no-store` or `no-cache`. In `orbit/catalog/app.py`, set `Vary: Authorization` and switched `Cache-Control` to `private` whenever responses include restricted scenes or user-specific data.

---

## What Was Seen
An analyst in Unit B (`analyst_b`) reported seeing scenes labeled `"RESTRICTED - Coast Guard Unit A"` when searching the Gulf of Kutch. These restricted scenes appeared when `analyst_b` performed the search shortly after a colleague in Unit A (`analyst_a`) had searched the same region. Upon refreshing a minute later, the restricted scenes disappeared.

## Reproduction Steps
1. Unit A analyst searches Gulf of Kutch through the gateway:
   `GET /search?bbox=69.0,22.0,70.5,23.5` with header `Authorization: Bearer tok-analyst-a-7f3c`.
   - Returns 25 scenes (10 public + 15 Unit A restricted).
   - Response header `X-Cache: MISS`, `Cache-Control: public, max-age=60`.
2. Within 60 seconds, Unit B analyst performs the exact same search:
   `GET /search?bbox=69.0,22.0,70.5,23.5` with header `Authorization: Bearer tok-analyst-b-91d2`.
   - Gateway returns `X-Cache: HIT` with Unit A's cached response.
   - Result contains 15 scenes labeled `"RESTRICTED - Coast Guard Unit A"`.
3. Refreshing after 60 seconds (once TTL expires):
   - Cache misses, catalog responds with only the 10 public scenes allowed for Unit B.

## Root Cause
1. **Cache Key Missing Authentication Context:**
   - In `orbit/gateway/cache.py`:
     ```python
     @staticmethod
     def key(request):
         return request.method + request.url.path + "?" + request.url.query
     ```
   - The key did not incorporate the `Authorization` header. As a result, requests with identical URLs from different users collided on the same cache key.
2. **Incorrect Cache-Control & Missing Vary Headers:**
   - In `orbit/catalog/app.py`, the `/search` and `/scenes/{scene_id}` endpoints returned:
     ```python
     response.headers["Cache-Control"] = "public, max-age=60"
     ```
     even when the returned scenes contained restricted data visible only to a specific unit.
   - The HTTP response omitted `Vary: Authorization`, failing to inform shared caches and proxies that responses are user-dependent.

## The Fix
1. In `orbit/gateway/cache.py`:
   - Updated `ResponseCache.key(request)` to include `request.headers.get("authorization")`:
     ```python
     @staticmethod
     def key(request):
         auth = request.headers.get("authorization") or ""
         return request.method + request.url.path + "?" + request.url.query + " " + auth
     ```
   - In `put()`, ensured responses with `no-store` or `no-cache` directives are not stored.
2. In `orbit/catalog/app.py`:
   - Updated `/search`:
     - Added `response.headers["Vary"] = "Authorization"`.
     - Set `scope = "private"` if any returned scene is restricted or if the user is authenticated with a unit affiliation.
     - Set `Cache-Control: f"{scope}, max-age=60"`.
   - Updated `/scenes/{scene_id}`:
     - Set `scope = "public" if row["restricted_unit"] is None else "private"`.
     - Added `response.headers["Vary"] = "Authorization"`.
     - Set `Cache-Control: f"{scope}, max-age=60"`.

## How We Know It Works
1. **Automated Unit & Integration Tests:**
   - Created `tests/test_t2_t3.py` with:
     - `test_t3_gateway_cache_key_varies_by_auth`: verifies that requests from Unit A, Unit B, and anonymous users produce strictly distinct cache keys.
     - `test_t3_catalog_headers_and_isolation`: verifies that queries returning restricted scenes emit `Vary: Authorization` and `Cache-Control: private`, and that Unit B never receives Unit A restricted scenes.
2. **Pytest Run:**
   - Executed `pytest tests`: all 12 tests passed cleanly.
