# Ticket T1: Search result outlines are drawn in the wrong place

## Brief Summary
- **Issue Name:** Search result outlines are drawn in the wrong place
- **Issue Explanation (Brief):** GeoJSON coordinates standard is `[longitude, latitude]`, whereas Leaflet's `L.polygon()` constructor expects `[latitude, longitude]`. Passing raw GeoJSON coordinates directly to `L.polygon` swapped the coordinates, placing Mumbai port footprints (~72.8° E, 18.9° N) far up in the Arctic Ocean (~72.8° N, 18.9° E, north of Norway).
- **Solution Explanation (Brief):** Transformed coordinate pairs from `[lon, lat]` to `[lat, lon]` before passing them to `L.polygon()`, and updated `highlight()` to update polygon styles in-place using a `featureId` attribute.

---

## What Was Seen
When searching around Mumbai port (approx. 72.7°–73.0° E, 18.8°–19.1° N), the search results list on the left correctly identified the matching scenes. However, the polygon footprints/outlines on the main Leaflet map were drawn far north in the Arctic Ocean (north of Norway/Barents Sea). Meanwhile, clicking on a result displayed the footprint accurately over Mumbai port in the detail panel map.

## Reproduction Steps
1. Start the portal backend services and web interface.
2. Select the "Mumbai port" search area (or draw a bounding box over 72.7–73.0° E, 18.8–19.1° N).
3. Execute the search.
4. Observe that result footprints appear in the Arctic Ocean near latitude ~72.8° N, longitude ~18.9° E instead of off the west coast of India.
5. Click any result item to inspect the detail panel and observe that the detail map renders the footprint in the correct location over Mumbai.

## Root Cause
- **Coordinate Order Inversion (`[lon, lat]` vs `[lat, lon]`):**
  - Standard GeoJSON defines coordinates in `[longitude, latitude]` (`[x, y]`) order. For Mumbai scenes, coordinates are roughly `[72.8, 18.9]`.
  - Leaflet's `L.polygon(latlngs)` constructor expects coordinates in `[latitude, longitude]` (`[y, x]`) order.
  - In `web/src/map/resultsLayer.ts`, `showResults()` took GeoJSON coordinates directly from `ring` and cast them as `L.LatLngExpression[]`:
    ```typescript
    const poly = L.polygon(ring as L.LatLngExpression[], STYLE);
    ```
    This passed `[lon, lat]` directly into Leaflet, causing Leaflet to interpret longitude $72.8^\circ\text{ E}$ as latitude $72.8^\circ\text{ N}$ (the Arctic Ocean) and latitude $18.9^\circ\text{ N}$ as longitude $18.9^\circ\text{ E}$.
- **Why the Detail Map Worked:**
  - `web/src/map/detailMap.ts` rendered the geometry using Leaflet's `L.geoJSON(...)` wrapper, which complies with the GeoJSON specification and automatically converts `[lon, lat]` pairs to Leaflet `[lat, lon]` tuples.

## The Fix
1. In `web/src/map/resultsLayer.ts`:
   - Transformed each coordinate point in `ring` from `[lon, lat]` to `[lat, lon]`:
     ```typescript
     const latlngs = ring.map(([lon, lat]) => [lat, lon] as L.LatLngTuple);
     const poly = L.polygon(latlngs, STYLE);
     ```
   - Attached `(poly as any).featureId = f.id;` so that polygon layers can be referenced during highlight operations.
2. In `highlight()`:
   - Updated the function to toggle the layer styling directly based on `featureId` instead of repeatedly appending extraneous `L.geoJSON` layers to the group on every selection.

## How We Know It Works
1. **Type Checking & Build Validation:**
   - Ran `npm run build` (`tsc --noEmit && vite build`) in `problem1-orbit-portal/web`. The build passed cleanly with zero type errors or bundle issues.
2. **Behavioral Verification:**
   - With the coordinate inversion resolved, `L.polygon` receives `[18.9, 72.8]`, positioning the footprints exactly over Mumbai port.
   - Polygons match the location rendered by `L.geoJSON` in the detail panel.
